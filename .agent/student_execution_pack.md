## 4. 三轮计时 Bug 练习

规则：由非实现者从下表抽题并保密；实现者先复现再修改。每次必须保存开始/结束时间、失败测试、最小补丁、回归输出和口头根因。

安全题库（不得触碰交易项目或真实发送）：

1. 官方 RSS 含裸 `&`，严格 XML 解析失败。
2. 同一标题修订后被错误当作新事件。
3. `received_at` 与 `published_at` 颠倒导致时间轴错误。
4. P2 传闻在没有 P0/P1 证据时误获告警资格。
5. 冲突证据存在却仍输出最终 S 级。
6. 模型文件损坏导致 API 崩溃而非可见回退。
7. 事件详情链接在 VPS 上错误指向 localhost。
8. 移动端事件队列无限增长，把证据区推到多屏之后。
9. 备份文件可生成但隔离恢复失败。
10. API 新字段破坏旧客户端或 envelope。
11. 事件后行情字段误进入模型特征。
12. OpenAPI 意外出现 order/position/balance 类路由。

## 6. 三分钟答辩主线

- 0:00–0:25：问题——新闻快，但不可复核；我们做证据终端，不做交易信号。
- 0:25–0:55：Situation Room——22 个分级来源、实时健康、最新事件和 no-trading 边界。
- 0:55–1:35：Event Intelligence——消息、声明、精确证据、修订和行情上下文同屏。
- 1:35–2:05：Replay——固定 SEC 案例证明证据不足时拒绝、证据到齐后再升级。
- 2:05–2:30：模型治理——分组留出集很好，但外部盲测正常新闻误报 95%，所以公开失败并保持 shadow。
- 2:30–2:50：工程可信——Worker、19/19公网产品、17/17行情能力、可恢复备份和换服务器包。
- 2:50–3:00：结论——“我们没有让模型更自信，而是让系统更会证明、更会拒绝、更能回放。”
