# Sprint 3：生产化、公开演示与最终收口

## Sprint Goal

把实验能力变成可公开演示、可持续运行、可安全恢复的正式产品，并将公共界面收敛到核心研究闭环。

## Sprint 范围

- AWS 上以 Nginx + systemd 部署 Web、API、Worker、模型、行情和备份；
- 隔离 Qwen 资源并修复长输入、CPU 竞争和队列公平性；
- 将 DeepSeek 调整为真实后台缓存，只展示已完成结果；
- 精简 Public UI，修复桌面主从布局、移动端、滚动和深链；
- 增加公共只读 GET API，同时保持内部入口非公开；
- 建立事务式发布、验证备份、失败回滚与公网验收；
- 完成展博会 6 页展示、应答手册、A4 卡片和现场演练材料。

## 部署与恢复流程

1. 校验 release manifest、依赖锁和关键文件；
2. 在切换前生成完整恢复包并隔离验证；
3. 暂停可能与切换竞争的 timers；
4. 安装候选 release，生成 Nginx 配置并执行 `nginx -t`；
5. 切换 release symlink，验证 loopback 与公网白名单；
6. 生成切换后的新恢复包并验证 ledger、operations、evidence 和 reports；
7. 仅在新备份验证成功后替换被取代的旧备份；
8. 恢复 timers 并写入 `ACCEPTED` 收据；
9. 任一门失败，回滚 release、服务、Nginx 和定时器状态。

## 公网安全验收

- Public UI 与白名单 GET API 可公网访问；
- POST、PUT、PATCH、DELETE 均被拒绝；
- OpenAPI、深度健康、模型状态、trace 和内部角色路径不可公开访问；
- Nginx 在转发前剥离 Authorization、Cookie、API key 和内部角色令牌；
- FastAPI 只监听回环地址；
- CSP 与 `X-Frame-Options` 阻止第三方 framing；
- 密钥不进入页面、仓库、报告或日志。

## Sprint Review

最终产品形成了“来源发现—事件账本—证据核对—Qwen 研判—DeepSeek 阅读—资产与价格—生产恢复”的完整链路。团队曾尝试接入另一套队友 UI，但右侧滚动、白屏重载、模型链路和登录门出现回归；最终回到稳定 `v2026.08.31.3`，再单独增加受控公共 API，避免为了视觉更新破坏核心闭环。

现场推荐演示顺序：

1. 在事件流搜索公司、Ticker 或事件；
2. 打开当前事件详情并核对来源；
3. 解释千问四字段与 DeepSeek 的不同职责；
4. 查看直接资产或代理资产及消息后价格；
5. 打开公共 API，说明 GET 白名单与内部边界；
6. 用版本、CI 和备份收据结束演示。

## Sprint Retrospective

### 做得好的地方

- 将慢模型、行情、采集和 Web 分离调度，单点失败不阻塞阅读；
- Qwen 使用公平轮转，避免只给最早一批事件评分；
- Public 不再展示长期“生成中”或无意义空卡；
- 生产发布具备备份验证、自动回滚和可追踪收据；
- 公共 API 增量没有扩大内部权限面。

### 后续研究方向

- 建立真正独立的人类盲测集，进一步验证模型外部泛化；
- 扩充混合极性、状态反转、否定与第三方对象 hard cases；
- 在不放松证据合同的前提下提高正式引用闭合率；
- 按真实命中样本扩充资产代理和交易日历；
- 继续执行桌面、手机、键盘和可访问性矩阵回归。
