# Sprint 1：从多源材料到可追溯事件账本

## Sprint Goal

建立只读事件雷达的最小真实闭环：来源可采、事件可归并、历史可追踪、页面可检索、失败可诊断。

## Sprint 范围

- 确立个人研究者优先、只读、no-trading 的产品章程；
- 注册监管、宏观、发行人和公开新闻线索来源；
- 建立原始观察、规范事件和不可变版本的数据链；
- 实现事件去重、原子化、搜索、筛选、分页和来源跳转；
- 建立 FastAPI、Public UI、持续 Worker 和基础自动测试。

## 关键架构决策

### 决策 1：先保存原始观察，再生成规范事件

原始材料即使没有立即形成事件，也要保留 URL、来源发布时间、本地接收时间、摘要和修订信息。这使团队可以重新归并和审计，而不必依赖抓取时的一次判断。

### 决策 2：事件不是文章标题

规范事件围绕主体、动作、事件族、时间和因果链建立。同一材料中的多个独立动作可拆分，多主题综述则保留为观察，避免生成没有可靠主语的伪事件。

### 决策 3：模块化单体优先

核心合同与账本共用一套 Python 代码，采集、Web 和 API 以独立进程运行。这样既保持迭代速度，又允许服务失败隔离，不为了展示而制造大量微服务。

## Sprint Review

Sprint 1 形成了可持续运行的事件流、来源追踪、事件版本、搜索筛选页面、基础 API 和自动测试。系统已从“新闻列表”转为“可回溯事件账本”。

现场可演示路径：搜索公司或事件 → 打开详情 → 查看事件日期与来源 → 返回筛选位置。

## Sprint Retrospective

### 做得好的地方

- 先建立不可变原始观察与版本链，为后续证据、模型和行情提供统一锚点；
- 把来源失败限制在单个任务，持续 Worker 不被一个供应商拖垮；
- 从第一轮就建立只读与 no-trading 安全边界。

### 暴露的问题

- 初版把“链接存在”和“事实已被原文支持”混成一个状态；
- 大量 SEC 文件标题只有提交日期、注册号和大小，对用户没有研究价值；
- 页面需要从“数据对象”进一步转为“用户能快速读懂的事件”。

### 结转到 Sprint 2

- 拆分材料可读性与事实证据强度；
- 生成语义事件标题并过滤元数据噪音；
- 接入风险语义、阅读辅助和事件后市场观察。

## Sprint 1 完成判定

- 核心数据链可追踪；
- Public 页面可连续操作；
- 来源失败不会阻塞总任务；
- 自动测试与安全边界通过；
- Review 中发现的问题已进入下一 Sprint Backlog。
