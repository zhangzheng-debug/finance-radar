# 金融雷达产品待办列表

## 1. 产品愿景

面向个人研究者，以最少点击完成“发现事件—核对原文—理解影响—观察市场反应”。

产品成功不以抓取条数或模型调用次数衡量，而以四个结果衡量：

1. 用户能找到正在发生的金融风险事件；
2. 用户能打开来源并核对支持段落；
3. 用户能看到有边界、可追溯的风险语义研判；
4. 用户能观察对应资产在消息发布后的真实市场反应。

## 2. 优先级与状态定义

- **P0**：缺失会破坏核心研究闭环或安全边界；
- **P1**：显著提升研究效率、覆盖率或可演示性；
- **P2**：体验优化或下一阶段研究；
- **完成**：已达到验收标准并进入当前正式版；
- **下一阶段**：不影响当前正式版演示，进入后续研究计划。

## 4. 当前正式增量

当前展示基线为 `v2026.08.31.3`，在其上增加提交 `e379edb33b71e33ad2fb0e0faa135e4eb257b1ed` 的公共只读 API。该增量不重新引入登录门，不暴露 Admin、Reviewer、Operator、模型状态、trace、OpenAPI 或写接口。

## 5. 产品验收边界

- 千问结果是风险语义研究辅助，不是事实证明；
- DeepSeek 是来源文本阅读辅助，不做风险评级；
- 行情是消息发布后的观察，不证明因果；
- IBIT 是美国上市 BTC 代理，不等同于 BTC；国家 ETF 是研究代理，不等同于事件主体；
- 带链接表示材料可访问，不自动升级为正式可引用事实；
- 公共端只读，无订单、仓位、余额或交易执行能力。

## 6. Backlog 维护规则

1. 每条待办必须有用户价值、验收标准、优先级和证据路径；
2. 新需求先判断是否强化核心闭环，再进入 Sprint；
3. 任何模型能力必须同时定义输入、输出合同、失效条件和展示条件；
4. 任何生产能力必须同时定义部署、监控、备份、回滚和公网验收；
5. 完成状态只由验收证据改变，不由口头说明或 UI 占位改变。
