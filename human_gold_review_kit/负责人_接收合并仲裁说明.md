# 负责人接收、合并与仲裁说明

## 分发边界

- 只把 `成员A_私密发送` 发给成员A。
- 只把 `成员B_私密发送` 发给成员B。
- `负责人材料_禁止发给组员` 含匿名凭据映射，绝不能发给审核员或提交到公开仓库。
- A、B都交回之前，不转发、截图或讨论任何一人的答案。

## 校验

```powershell
python scripts/human_gold_review_kit.py validate --assignment "assignment_A.json" --submission "成员A交回.gold-review.json"
python scripts/human_gold_review_kit.py validate --assignment "assignment_B.json" --submission "成员B交回.gold-review.json"
```

校验会拒绝：缺条目、错误匿名凭据、无效三轴、少于20字的理由、未勾选真人独立审核声明、试图提交最终标签或附带额外价格/模型字段。

## 双审合并

```powershell
python scripts/human_gold_review_kit.py merge `
  --owner-manifest "owner_manifest.json" `
  --submission-a "成员A交回.gold-review.json" `
  --submission-b "成员B交回.gold-review.json" `
  --output "合并结果" `
  --zip "合并结果.zip"
```

三轴完全一致才形成 `CONSENSUS`。任何一轴不同，都不会被多数猜测覆盖，而是进入 `第三人仲裁包_私密发送`。

## 第三人仲裁

第三人必须不是成员A或成员B。把仲裁包单独发给第三人，收回其 `.gold-review.json` 后：

```powershell
python scripts/human_gold_review_kit.py finalize `
  --merge-manifest "合并结果\merge_manifest_private.json" `
  --arbiter-submission "仲裁交回.gold-review.json" `
  --output "human_gold_annotations_unassigned.jsonl" `
  --report "human_gold_finalize_report.json"
```

## 冻结为训练 / 验证 / 密封盲测

`finalize` 输出仍是 `split=UNASSIGNED`。先运行冻结闸门：

```powershell
python scripts/freeze_offline_human_gold.py `
  --annotations "human_gold_annotations_unassigned.jsonl" `
  --report "human_gold_freeze_readiness.json" `
  --dataset "human_gold_frozen.jsonl"
```

默认要求 720 条。冻结器只根据审核前已经固定的来源元数据，自动选择数量足够且可完整
留出的最大来源族放入密封盲测；其余样本继续按事件 `as_of` 保持时间顺序，分为训练 420、
验证 120，并用最新的非留出样本补足密封真人盲测 180。也可以在审核完成前用
`--holdout-source-family <来源族>` 固定负责人已预先声明的来源族，不能根据标签或模型结果
事后挑选。冻结仍要求发行人、事件链、精确文本和近重复零交叉、至少四个独立来源族，
且盲测中存在训练/验证完全未见的来源族。标签数量不足或无法形成真实来源留出时只输出
`NOT_READY_TO_FREEZE` 和具体缺口，不生成数据集。

类别数按自然真人结论检查，不为了凑数而重排或改标签。最低底线分别为：训练集
`RISK_REVIEW 40 / NON_TARGET 100 / ABSTAIN 20`，验证集 `10 / 20 / 5`，
密封盲测 `20 / 30 / 5`。盲测执行时还会再次要求至少 20 条
`PRIORITY_REVIEW`；不足只能保留为开发或 Shadow 工件，不能晋级生产。

冻结后的原始 TRAIN 仍一条一条保存。训练准备器只为降低小模型多数类塌缩，在
TRAIN 内把 `PRIORITY_REVIEW` 提到最多 25% 的有效训练占比，每条最多出现 4 次，
并留下 origin/repeat 审计字段。验证集和盲测集严禁复制或配平。

## 最终边界

冻结工具只生成有哈希的数据工件；它不修改生产事件、服务器或模型。即使状态为
`READY_TO_FREEZE`，也不等于模型已经训练、晋级或部署。任何模型晋级仍需单独评估和发布门。
