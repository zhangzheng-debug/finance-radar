# Finance Radar · 后续开展建议书

> 作者：Claude（claudeUI 工作区）· 2026-07-19
> 依据：v5.1 AI 任务书、README、ACCEPTANCE_STATUS、现有五页终端源码、
> 公网站点实际运行状态。所有建议都尊重现有停止规则
> （P0/P1 未全绿前不加 PostgreSQL / React / K8s / Redis / Celery / 交易能力）。
> 本文只谈工程与产品，不构成任何投资建议。

---

## 一、当前判断（一句话版）

**这个项目的稀缺性不在"又一个新闻聚合"，而在"可审计"三个字**：
不可变账本、内容寻址证据、诚实的 MISSED_WINDOW、公开的模型失败报告、
双人盲标与第三人裁决。后续所有投入都应该放大这个差异点，
而不是稀释它去追功能数量。

## 二、近期（答辩前）：只做收尾，不加功能

剩余红项全部是外部/时间型（教师批准、学生禁飞区、24h 窗口、
当前 release 浏览器 QA 矩阵、真实双人裁决）。建议：

1. **功能冻结**。任何新特性都会重置浏览器 QA 基线，得不偿失。
   claudeUI 的 Streamlit 补丁若要合入，应与本轮 QA 刷新**合并为一次**，
   避免刷两遍矩阵（这是把 UI 升级排进这个时间点的最大理由）。
2. **把 24 条盲标任务真正标完**。这是唯一能证明「人在环」不是摆设的证据；
   两名审核者 + 一名裁决人，按 v3 合同一次走完，冲突样本反而是答辩亮点。
3. **答辩排练走"三分钟路径"**：态势室 → 最新真实事件 → SEC 回放 →
   正面/冲突对照 → 模型消融与漂移策略 → 备份恢复与无交易边界。
   每一步都有机器验收报告兜底，排练时把对应报告路径背熟。

## 三、UI/UX 路线图（本目录交付物的使用顺序）

| 批次 | 内容 | 前置条件 | 风险 |
|---|---|---|---|
| 1 | `streamlit_patch/style_v2.css` 整体替换 + 图表配色 | 无（纯 CSS） | 低；需刷新一次 QA 矩阵 |
| 2 | 权威 chip / 冲突证据卡两处 markup 增强；Ctrl+K 命令面板组件 | 批次 1 合入 | 中；补 AppTest |
| 3 | 顶部导航 + 三栏 Workbench（`prototype/index.html` 形态） | P0/P1 全绿、答辩结束 | 高；属于形态迁移 |

批次 3 的技术路线建议：**不上 React**。原型已证明纯 HTML/CSS/JS
（零依赖、零构建）能承载全部五页交互。若届时想脱离 Streamlit，
可以让 FastAPI 直接 serve 这个静态壳（同源，无 CORS 问题），
Streamlit 版并行保留作为运维后台。这条路线不触碰任何停止规则，
且离线演示包也能直接复用同一个静态壳。

另外三个纯前端的低成本高感知改进（批次 2 可顺带）：

- **事件流极性 glyph**（▼▲◆◈）：一眼区分利空/利好/中性/冲突，
  且用形状不靠颜色，机审无障碍门直接受益。
- **来源健康 22 格热力图**（原型右栏样式）：比现在的四格计数更能
  在答辩大屏上"一眼看出系统活着"。
- **KPI 迷你趋势线**：worker 周期、证据对象增长画 12 点 sparkline，
  证明"部署后采集没有停"这句话不用翻报告。

## 四、产品方向（答辩后 3-6 个月）

按「放大可审计差异点」排序：

1. **公开证据档案浏览器**。`/api/v1/evidence/archive` 已有 95 个不可变
   原文对象，做一个只读页面：SHA、抓取时间、来源域名、MIME、原文快照
   渲染。这是别家没有的"证据可自查"卖点，且纯只读、零合规风险。
2. **事件族时间线视图**。同一 event_family 的事件在横向时间轴上聚合
   （P2 发现 → P0 确认 → 修订 → 撤回），把"证据链"从概念变成可看的图。
   数据 `/events/{id}/timeline` 已齐，纯前端工作。
3. **每日情报摘要（Telegram/邮件 digest）**。现有 outbox + 深链已具备，
   加一个"每日 UTC 00:00 汇总昨日 RISK_REVIEW + 冲突弃权事件"的模板，
   仍然保持显式 `--send`。这是把系统从"要人来看"变成"会来找人"的一步。
4. **检索升级到 SQLite FTS5**。当前 `q` 是 LIKE 匹配；FTS5 是 SQLite
   内置能力，不引入新组件，就能支持词组/前缀/排序，账本 1.2k 事件规模
   下毫秒级。这是合规于停止规则的最大检索收益。
5. **多用户与角色**（若要对外）：审核人/裁决人/访客三角色 + 每角色
   rate limit。在此之前公网写控件保持默认关闭是对的。

规模阈值提示：SQLite WAL 在当前写入模式（单 worker、5 分钟周期）下
可以支撑很久；只有出现多写者并发或账本 >10GB 时才值得重新讨论
PostgreSQL，且届时 P0/P1 应已全绿。

## 五、模型治理（保持纪律，换打法）

外部盲测 v1 的失败诊断（内部分类捷径 + 无代表性负样本）已经指明方向：

1. **先修标签，再修模型**：按 v3 合同攒够真实双人内容裁决，
   冻结 evidence-enriched blind v2，然后才谈候选晋级。现在的
   877 行候选被机器门禁拦下是制度在起作用，不要绕。
2. **小模型定位维持"高召回路由 + advisory summary"**。0.5B 模型
   判 claim 的 8/8 失败报告是宝贵资产，答辩和文档里继续公开。
   若想提升 Evidence Agent 摘要质量，优先升级到 1.5B-3B 量化模型
   （VPS 内存允许的话），职责边界不变：只写 advisory，不改判定。
3. **特征侧最有性价比的一步**：把"确认事实 + 精确证据段落"作为
   模型输入合同的强制字段（v2 候选已验证方向正确，只是覆盖率不够），
   配合 blind v2 重新评估。目标不是 accuracy 好看，而是
   ECB/EIA 这类留出来源上的泛化。
4. **漂移监控落地成页面**：drift_warn 阈值已定义在模型卡里，
   Operations 页加一行"当前 abstain/risk_rate/confidence 相对基线的 Δ"，
   让阈值从文档变成看得见的仪表。

## 六、工程与运维

1. **GitHub 仓库补 CI**：tests <60s，直接上 GitHub Actions 跑
   `pytest + compileall`，PR 必绿。同时满足课程对"真实提交历史"的要求——
   小步提交、真实 diff，别再攒大包（当前仓库只有 3 个初始化提交）。
2. **状态页**：把 `runtime_gate_latest.json` 渲染成公开 `/status`
   （哈希链最新 PASS/FAIL、worker 周期、来源健康计数）。运维证据
   已经每 15 分钟在产出，缺的只是一个展示面。
3. **备份恢复演练日历化**：现在的隔离恢复演练是里程碑式的；
   建议固定每月 1 次全流程（已有脚本，纯执行成本），
   并把最近一次演练日期显示在 Operations 页。
4. **域名与 TLS**：sslip.io + 8443 适合答辩，长期建议买一个正式域名
   （年成本 ~$10），Nginx 配置几乎不变，Cloudflare 只做 DNS 不做代理，
   避免现在 sg.zb1og.cn 的人机验证问题再现。
5. **安全小项**：API 目前全公开只读——建议对 `/adjudication/*` 之外的
   写路径（human-override、agent/run）也加显式 token 审计日志
   （代码里已有 ADMIN_TOKEN 机制，确认公网默认关闭即可）；
   Nginx 层对 `/finance-radar-api` 加基础 429 响应头方便客户端退避。

## 七、一个诚实的提醒

系统当前最薄弱的环节不是代码，是**真实人工复核量为 0**
（1194 个事件、297 条待复核、0 条 adjudication review）。
所有制度设计都在等真人进场。答辩前把 24 条盲标走完、
答辩后建立"每周固定复核时段"，比任何新功能都更能让
这个系统从"可审计的架构"变成"被审计过的系统"。
