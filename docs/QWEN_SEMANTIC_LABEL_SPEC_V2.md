# Qwen 风险语义标签规范 v2

## 目标与边界

本规范用于构造下一版 Qwen 的语义监督数据。模型回答的是：**来源文本表达的事件，对文本中的主要受影响主体是否构成重大下行，以及方向是什么。**

它不回答事件是否真实，不读取来源等级、旧标签、审核人答案、Qwen 预测或消息后的价格结果，也不产生投资建议。DeepSeek 多视角结果属于 `AI_MULTIVIEW_SUPERVISION_NOT_HUMAN_GOLD`，不能包装成人工金标。

## 最终标签

### 重大性 `materiality`

- `MATERIAL_ADVERSE`：文本给出已发生、已生效或正式决定/承诺的事实，并存在直接作用于主要主体的实质下行机制。
- `NOT_MATERIAL_ADVERSE`：不构成主要主体的实质下行，包括普通披露、正面或中性事实、纯假设/合同定义、仅第三方受影响、风险已经真正解除、以及没有新事实的重复报道。处于整改期本身不等于正式退市，但若文本给出直接且重大的下行机制，仍可判为 `MATERIAL_ADVERSE`。
- `UNCLEAR`：文本无法确定主体、动作、状态或重大性。它不是“不想判断”的默认选项。

### 极性 `polarity`

- `ADVERSE`：主要主体的下行因素占主导，文本没有同等实质的正面抵消。
- `POSITIVE`：改善、批准、达标、解除缺陷或风险消除等正面因素占主导。
- `NEUTRAL`：信息性或方向不明显，且文本本身足够清楚。
- `MIXED`：**同一主要主体**同时存在独立且有意义的正、负因素。例如融资显著延长现金跑道，同时造成重大稀释。审核人意见冲突、主体不清或状态不明不能标成 `MIXED`。
- `UNCLEAR`：文本不足以确定方向。

## 四个机制轴

最终标签前必须先判断：

1. `event_realization`：已发生/生效、正式决定/承诺、拟议/附条件、假设/合同定义、无法判断。
2. `subject_relation`：主要主体、第三方、一般市场、无法判断。
3. `risk_status`：风险活跃、整改期尚未结束、负面条件确已解除、无负面状态、无法判断。“案件已解决”若结果是罚款、禁令、判决或和解责任，仍属于风险活跃，不属于条件解除。
4. `novelty`：新事件或状态变化、无新事实的重复/重述、无法判断。

这四个轴解决旧模型最常见的关键词误判：

- 合同中写有“bankruptcy”不等于破产已经发生。
- 监管处罚第三方不等于当前发行人被处罚。
- 缺陷解除不是新的纯负面事件。
- 收到最低价整改通知不等于交易所已经作出正式退市/停牌决定。
- 同一事实的再次报道不等于新事件；只有新增决定、生效、金额、结果或状态反转才算新状态。

## 多视角盲审

脚本 `scripts/adjudicate_qwen_semantic_multiview_v2.py` 对每条匿名文本执行三次调用：

1. **事实/机制审查**：识别谁做了什么、是否生效、作用对象和具体机制。
2. **反证/边界审查**：独立检查假设、第三方、风险是否真正解除、整改期和重复事件；它看不到第一次结果。
3. **仲裁**：同时看到原始文本和两个隔离观点，重新按规范裁决；不会按多数票或平均标签处理。

输入严格限定为：

```json
{"sample_id":"local-only-id","content":{"headline":"...","summary":"...","passages":[]}}
```

`sample_id` 不发送给模型。内容中出现旧标签、重大性/极性答案、审核答案、Qwen 输出或市场结果字段时，脚本在调用 API 前拒绝执行。每条输出保留两个隔离观点、最终标签、机制轴、稳定 `reason_codes`、内容哈希及是否首轮一致，便于错误聚类和后续 SFT。

模型若给出明确机制轴但漏掉由该轴唯一推出的理由码，脚本会确定性补齐理由码后再校验，例如 `novelty=NEW_EVENT_OR_STATUS_CHANGE` 必然补入 `NEW_MATERIAL_FACT_OR_STATUS_CHANGE`。补全过程不改变重大性、极性或任何机制轴；不能唯一推出的事实（例如“已经正式退市”）绝不自动补写。

长批次中断后可使用同一命令附加 `--resume`。恢复只接受对应输出目录的 `.in-progress`，并在读取密钥或调用 API 前核对原始输入 SHA-256、监督合同、Qwen 合同、DeepSeek 模型和样本数。脚本验证进度账本中每个已完成结果与当前内容哈希，跳过已完成项，只重试失败或缺失项；不可解析的最后半行会被安全截断。全部完成后仍以目录重命名原子发布。密钥和密钥文件路径均不写入状态、进度或最终产物。

## 训练与检验规则

- 监督集按 `entity_group` 与 `event_chain_group` 分组切分，禁止同一实体/事件链跨训练与盲测。
- 同一来源的重复文本先去重；重复报道只能作为“重复/重述”负例，不得复制成多个训练权重。
- 必须单列 `MIXED`、`UNCLEAR`、第三方、合同定义、整改期、问题解除和重复事件的支持数与召回率。
- 用于调参的样本即视为开发集；后续效果必须在从未用于提示、规则或参数选择的新盲集上检验。
- 通过离线门槛也只能先进入影子运行，不改变事件事实、证据状态或交易能力。
