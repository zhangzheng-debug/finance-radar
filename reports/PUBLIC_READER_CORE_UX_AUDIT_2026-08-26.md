# Finance Radar 公共读者核心体验审计

日期：2026-08-26
范围：Claude 用户体验审计、Public API、Streamlit Public 页面、采集准入、模型展示与价格审计
结论：Claude 指出的主要体验问题成立；问题根源不是颜色或组件数量，而是内部流程语义侵入 Public 产品。

## 1. 产品核心

Public 用户真正需要完成四件事：

1. 快速发现潜在下行事件；
2. 看懂谁做了什么；
3. 打开来源材料核对；
4. 在结果已完成时查看模型风险语义和消息后的价格反应。

人工核验进度、Worker、队列、数据库字段、模型运行时和备份状态属于内部工作面，
不应成为 Public 导航或主内容。

## 2. Claude 审计复核

| 发现 | 判断 | 处置 |
|---|---|---|
| 卡片标题只是公司名 | 成立 | 改为事实标题、来源归因标题或中性档案标题 |
| 首个事件位置过低 | 成立 | 删除 Evidence Desk、KPI 状态条和公开流程筛选；高级筛选折叠 |
| 大量重复边界文字 | 成立 | 边界只在方法页和 DeepSeek 触发处各说明一次 |
| 点击详情慢 | 成立 | 单个 dossier 读取、同页详情、缓存与降级路径；不再串行读取五个端点 |
| 分页后停留页面底部 | 成立 | 顶部/底部分页共用同页定位动作；换页后返回事件区并清理临时参数 |
| 来源内容重复 | 成立 | 标题与摘要去重、限长；详情直接展示一段最相关来源摘录 |
| 更新时间相互覆盖 | 成立 | 列表只保留一个更新时间；详情只保留来源发布与数据更新 |
| 央行音乐会被当事件 | 成立 | 新数据准入前过滤；旧候选自动退回来源档案 |

## 3. 模型职责

- **千问**：未来的核心风险语义模型。只使用双人独立金标完成训练、盲测和发布批准后
  的结果，输出方向、重大性和下行强度。没有获批结果时 Public 不显示模型模块。
- **DeepSeek**：只在事件完全没有证据关系、没有一手来源待回抓、但有 API 捕获文本
  时解释该文本。它不确认事实、不改变千问标签、不参与价格审计。
- **确定性规则**：负责准入、来源层级、字段完整性和安全隔离，不在 Public 页面冒充
  “模型研判”。

## 4. 展示合同

- 数据存在且可解释才创建模块；空、排队、重试和失败不创建公共卡片。
- 原始材料优先于模型说明。
- 价格反应只显示完成的固定窗口收益；不显示任务状态、错过窗口或供应商错误。
- 明确非金融来源记录不计入公共事件总数，但原始捕获仍留在内部审计链。
- Public 只保留三个入口：事件雷达、案例、方法。

## 6. SPA/PWA 决策

这次不同时引入第二套前端。当前同页详情已进入亚秒可读范围，重写 SPA 会扩大接口、
部署、缓存和双端一致性风险，却不能替代事件标题、内容层级和模型展示合同。标准部署后
先测 14k 生产账本的 P50/P95；只有暖点击 P95 仍超过 1 秒或冷点击 P95 超过 2.5 秒，
再以现有 Public DTO 建轻量 SPA/PWA，并保持内部 Streamlit 工作面不变。
