## 3. 最初目的与当前形态

### 3.1 最初目的

V2 将产品定义为面向美股、ETF、宏观、商品、外汇和主要加密资产的**个人财经事件雷达**：把官方原文、聚合新闻、社交线索、交易所公告、异常和公开行情转换为可核验、持续更新、可复盘的事件对象与 Telegram 线程（`financial_event_radar_project_plan_v2_0_ai.md:42-57`）。

成功标准包括快速发现硬事件、压缩重复报道、区分事实/来源/严重度/资产影响、用可靠来源核验、观察而非臆测市场反应，以及保存可回放、可标注、可审计的证据链。自动交易、投资建议和机构级超低延迟终端从一开始就是非目标（同文件 `:59-66`）。

### 3.2 当前形态

当前代码和文档描述的是部署在 AWS 的只读金融事件证据系统，包含公网浏览、内部人工复核、模型治理、确定性回放、运维诊断、备份恢复、离线演示和课程证明材料。V6 仍将其定义为只读、可追溯、可回放的系统，要求人作最终判断（`financial_event_radar_project_plan_v6_0_ai.md:43-57`）。

因此它不是换成了另一个项目，而是在相同证据内核上形成了很强的工程与演示外壳。

## 4. 保持一致的部分

- **证据优先**：保存原文、修订、证据边和时间，弱证据或冲突不得自动成为事实。
- **全极性发现、下行风险优先路由**：正面和中性事件仍采集，模型只辅助风险复核排序。
- **人工最终判断**：AI、影子模型和小模型均不能自动确认事实。
- **无交易边界**：API 和测试明确禁止订单、账户、持仓和余额能力（`tests/test_product_layer.py:220-280`）。
- **多源覆盖**：采集器仍定义 Fed、SEC、CFTC、FDA、FTC、FDIC、NVIDIA、ECB、EIA 等来源（`scripts/official_event_collector.py:63-190`）。
- **回放与可恢复性**：历史事件、失败状态和备份恢复仍服务于原来的可复盘目标。

### 8.4 P1 发现与本轮处理

1. **受保护备份可能在实体已经丢失时仍被健康接口表述为 `FRESH`。**
   API 进程无法穿越 root 备份目录时，文件存在与文件丢失都可能表现为
   `PermissionError`，而旧逻辑只根据运维库的最近 `VERIFIED` 时间判断新鲜。
   本轮已按诚实降级原则处理：低权限 API 无法证明实体存在时返回
   `UNVERIFIABLE_PROTECTED`、`fresh=false` 和整体 `degraded`，不得宣称 `FRESH`。
   后续仍可增加与 manifest 绑定、由备份流程原子更新的公开状态收据。
2. **过期备份锁回收存在双竞争者 TOCTOU。** 两个进程可能先后把对方的新锁
   当成旧锁移走，造成并发备份与裁剪。本轮已引入覆盖完整备份事务的跨平台内核
   文件互斥（POSIX `flock` / Windows byte lock），并加入双进程并发竞争测试。
3. **人工 override 可能引用已经过期的 Evidence Agent 决策。** Worker 已经按
   event version 和 evidence receipt 拒绝旧决策，但原人工写入路径未执行同样核验。
   本轮已在写入前重算当前收据，不一致返回 `409 STALE_AGENT_DECISION` 且不写审计行。
4. **关键实现最初处于未跟踪状态。** 证据策略、systemd slice、备份静默包装器、
   收据校验器和 release identity 若漏交，干净克隆将与本机测试环境不同。本轮发布
   必须显式纳入这些文件，并在新提交的 GitHub CI 中复跑。

前三项已通过 51 项定向回归和 `629 passed, 5 skipped` 全量回归。它们仍需 GitHub
CI 和真实 Linux 部署验收，不能仅凭本地测试写成生产已修复。

### 8.5 P2 待办

- **依赖不可重复解析**：`requirements*.txt` 仍大量使用下限版本，没有带哈希的
  锁文件或 wheelhouse；同一源码在不同日期可能获得不同运行环境。
- **Worker 租约短于允许的最长周期**：live-cycle 默认租约 300 秒，而连续 Worker
  允许子进程最长约 600 秒；应续租或把租约与监督进程生命周期绑定。
- **公网限流语义**：Public Streamlit 经 loopback 调 API，访客在 API 侧共享
  `127.0.0.1` 桶；不能再称为“每公网客户端 180 次/分钟”。
- **可选本地 LLM 会与采集冲突**：手工启动前要求停 Worker/备份是安全的，但
  `enable --now` 可能让一次演示变成持久开机服务。应改为限时、非 boot-enabled
  的维护会话，结束后由操作者明确恢复采集。
- **单一本机恢复点**：实现忠实执行“每天一份、新换旧”的用户决定，但逻辑误删
  也可能被完整备份并替代唯一旧点。建议本机仍保持一份，异机加密恢复点独立保留
  7 个日期版本；该策略变更需要额外成本与授权，未在本轮执行。
- **启发式分数呈现**：无模型工件时的关键词 fallback 不是校准概率。本轮已把
  `confidence_applicable` 改为 false；UI 和后续报告仍应称其为规则分数。
- **真实复核不足**：基础设施、备份和演示证据远多于真实不同人员复核、冻结盲测
  与产品 KPI。P1 收口后应冻结新的基础设施扩张，先获得人工结论质量证据。

### 8.6 P3 防御性改进

- 管理令牌比较可改用 `hmac.compare_digest`；
- 内存限流桶需要过期键清理；
- 文件树的 symlink 检查与复制之间仍有低概率竞态，可逐步改成 descriptor-relative、
  no-follow 复制；
- 多数 systemd/Nginx 测试是源码合同，不能替代真实 Linux cgroup、权限、路由和
  timer 验收。

## 10. 最终判断

Finance Radar 的证据优先、只读、多源、人工最终判断和可回放内核没有改变。偏差主要发生在资源配置与叙事中心：课程、模型、恢复和工程证据逐渐主导了仓库与路线图，而个人研究者的发现、筛选、关注和提醒工作流没有获得同等投入。

正确方向不是删除安全、审计、演示和恢复能力，而是让它们重新服务于首要产品闭环：**发现事件，快速回到原始证据，诚实表达不确定性，帮助个人完成判断。**
